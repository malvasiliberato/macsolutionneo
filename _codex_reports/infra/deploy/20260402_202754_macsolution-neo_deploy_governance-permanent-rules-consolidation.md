# Come usare da ora queste regole nei task successivi
- Formulare i prossimi task per bounded context o macro-step leggibili.
- Dare per acquisite le regole permanenti su:
  - legacy vs target;
  - backend-first / API-first / mobile-ready;
  - reportistica in `_codex_reports`;
  - obbligo di mapping/import legacy per bounded context con impatto dati.
- Aprire step nuovi solo quando esiste un vero deliverable distinto o un boundary nuovo.

# Nota pratica sui prossimi prompt
- E' ora sufficiente chiedere il prossimo macro-step in forma umana e diretta, per esempio su:
  - `pricing profile foundation`
  - `reconciliation output auth/org`
  - `catalog import mapping`
- Non serve piu' ripetere ogni volta l'intera cornice metodologica di base.
